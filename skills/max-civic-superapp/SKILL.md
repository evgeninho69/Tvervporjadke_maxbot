# MAX Civic SuperApp

Skill для проектирования "полной" версии городского сервиса на базе бота + мини-приложения + админ-системы.

## Когда применять

- Пользователь просит "production-версию", "не MVP", "полезно для города".
- Нужно сформировать полный каталог функций и дорожную карту.
- Нужно согласовать фичи одновременно для граждан и администрации.

## Фрейм проектирования

1. Раздели фичи по слоям:
   - Core platform
   - Citizen UX
   - Admin/Municipality UX
   - Data/AI
   - Operations/Security
2. Для каждой фичи укажи:
   - ценность
   - сложность
   - риск
   - зависимость от внешних систем
3. Обязательно включай:
   - SLA и эскалации
   - юридические/PII ограничения
   - метрики успеха и мониторинг

## Стандарт выхода

При ответе пользователю давай:
1. Короткий целевой образ production-системы.
2. Список обязательных доступов/интеграций.
3. "Избыточный" каталог функций (для последующего отсечения).
4. Рекомендованный порядок внедрения (wave 1/2/3).

## Обязательные operational акценты

1. План B на случай проблем с публичным webhook:
   - переключение на polling
   - оперативная диагностика через `GET /updates`.
2. Ротация токенов:
   - если токен утек в переписке/логах, немедленный revoke/regenerate.
3. Reverse proxy contract:
   - отдельное правило для `/integrations/max/webhook`
   - не допускать, чтобы webhook route отдавал frontend HTML.
