# MAX UI Mini App

Используй этот skill для задач, где бот дополняется полноценным интерфейсом: формы заявок, карта, личный кабинет, аналитика.

## Когда применять

- Есть запрос "сделать мини-приложение в MAX".
- Нужна UI-часть для сложных сценариев, неудобных в чате.
- Нужны UX-флоу: создание заявки, трекинг статуса, подписки, документы.

## Принципы

1. Чат для быстрых действий, mini app для сложных действий.
2. Любой критичный action в UI должен иметь подтверждение и аудит.
3. Mobile-first, слабая сеть и старые устройства учитываются по умолчанию.
4. PII минимизировать, чувствительные действия только после проверки сессии.

## Рекомендуемые флоу

1. Главный экран:
   - "Создать заявку"
   - "Мои заявки"
   - "Новости района"
   - "Экстренные сообщения"
2. Форма заявки:
   - категория
   - адрес/точка на карте
   - фото/видео
   - описание
3. Карточка заявки:
   - статус, SLA-таймер, история изменений
   - чат с оператором
4. Профиль:
   - подписки по темам/району
   - каналы уведомлений

## Технический минимум

- SSR/edge caching для быстрых первых экранов.
- Optimistic UI + фоновые ретраи на отправку.
- Feature flags для безопасного включения новых функций.
- Бюджет производительности: быстрый first paint и стабильный input latency.

## Связка с ботом (практика)

1. Бот должен отдавать прямую ссылку на mini app текстом (даже если кнопки не поддерживаются клиентом).
2. Mini app URL держать в одном env (`MAX_MINIAPP_URL`), использовать его и в боте, и в UI-конфиге.
3. Если mini app и webhook живут на одном домене:
   - route `/integrations/max/webhook` должен идти в bot service
   - остальные пути в mini app frontend
